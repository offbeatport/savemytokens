5 recently released (last ~12–18 months)

New entrants that are genuinely valuable for cutting AI cost — and where each one is still thin.

Together AI Batch Inference API

Recent

Launched Jun 2025; 3000× rate-limit upgrade (→30B tokens/model) through 2025–26.

Why valuable
Flat 50% off Together's already-cheap open-model rates for any latency-tolerant bulk work (synthetic data, labeling, offline evals, log enrichment). Discount stacks on a low base; bulk jobs run on a separate rate pool so they never throttle production.
Pricing
50% off list, pay-per-token, no minimum, pay only for successful completions
Gap
Open models only (no GPT/Claude/Gemini); best-effort 24h SLA; the 50% is undifferentiated (Fireworks & Groq match it); JSONL prep + polling overhead persists.

Bifrost by Maxim AI

Recent

2025 entrant; ~5.9k★, very active (CLI v0.10.6, Jun 2026).

Why valuable
OSS (Apache 2.0) Go gateway, drop-in OpenAI-compatible. Three levers: semantic caching, automatic failover + adaptive load-balancing to cheaper/healthier endpoints, and a 4-tier budget hierarchy with hard per-key spend caps. Go architecture cuts infra cost vs Python LiteLLM at high RPS.
Pricing
OSS core free to self-host; enterprise custom (undisclosed)
Gap
Perf claims vendor-published & unconfirmed; gateway overhead is <1% of call latency (edge is niche); no managed/hosted option for OSS core; observability steered to Maxim's paid platform.

Requesty

Recent

$3M seed (20VC), Sept 2025. The EU-focused OpenRouter alternative.

Why valuable
Managed router over 400+ models. One base-URL swap → task-based routing (cheap models for simple tasks), prompt caching, failover, per-user spend caps, governance (RBAC, PII masking, SSO), and EU/GDPR residency. Claims 30–80% savings; differentiates on governance + compliance.
Pricing
Free 200 req/day; PAYG flat 5% markup, no minimum; enterprise custom
Gap
Cloud-only (no self-host) rules out sovereignty buyers; 5% markup compounds (~$5k/mo at $100k spend) while rivals market "no markup"; thin independent validation; early-stage key-man risk.

Batchwork

Recent

Brand-new: npm Jun 2026, 5 versions in ~10 days.

Why valuable
MIT npm package: one unified batch API over 7 providers (OpenAI, Anthropic, Gemini, Groq, Mistral, Together, xAI). Serializes the right provider batch body, tracks lifecycle, returns one normalized result. Captures each provider's native ~50% discount with no markup.
Pricing
Free / OSS — savings flow straight from providers' batch endpoints
Gap
Bus-factor of one, days old (real abandonment risk on a cost-critical path); batch support uneven across the 7; polling-based (you own crash durability); crowded field with thin differentiation.

Redis LangCache

Recent

Public preview Sept 2025; still preview Jun 2026 (GA pricing TBD).

Why valuable
Fully managed semantic cache: returns stored responses for semantically similar (not just identical) queries. Redis handles embeddings, vector search, TTL, scoping — so you skip operating GPTCache. A cache hit skips the LLM call entirely, killing output-token cost (~40–73% on high-repetition workloads).
Pricing
Free in preview; GA TBD (~$1.5/M input illustrative + Redis Cloud)
Gap
Silent false positives — a confidently-wrong cached answer at 200 OK (0.88–0.94 cosine danger zone) with no correctness instrumentation; manual threshold tuning; misses hidden context (permissions, locale, staleness).

5 mature (established, real adoption)

The proven workhorses customers already rely on — including the two free native features that quietly beat most paid tools.

Anthropic Prompt Caching native

Mature
Why valuable
Highest-leverage single change for high-volume Claude workloads with large static prefixes. Cache reads bill at 0.10× input (90% off); break-even after ~2 hits. Real cases: $8,000→$800/mo (10×), 59% total cut at 84% hit rate. Output byte-identical, minimal code, stacks with Batch for 95%+ combined.
Pricing
No fee — token multipliers (write 1.25×, read 0.10×)
Gap
Exact-prefix-match & fragile (any drift cascades); silent min-prefix (think you're saving, you're not); 5-min TTL fragile for bursty traffic; past billing bugs caused 10–20× overspend.

OpenAI Prompt Caching native

Mature
Why valuable
Cuts repeated-prefix input cost up to ~90% and latency ~80% with zero developer action — automatic on any prompt >1,024 tokens, default-on across the lineup. Stacks with Batch (50%) for ~75% total input-cost reduction on async work.
Pricing
No fee, applied automatically (GPT-5.x cached ~10% of standard)
Gap
Exact-prefix-match only; routing-overflow under load drops hit rate (one report: 3.77% on a 100k-token prompt); <1,024-token prompts never cache; no SLA, no manual cache control, no way to force/inspect a hit.

OpenRouter

Mature
Why valuable
Hosted marketplace for 400+ models with automatic routing to the cheapest/available provider + failover, so failed requests don't waste spend. No per-token markup; one key, unified billing, day-one new models, zero-infra adoption (swap base URL). BYOK free up to 1M req/mo.
Pricing
~5–7% all-in (5.5% card fee, 5% BYOK overage); no subscription
Gap
No SLA / single point of failure (3 outages in 8 months); silent quantization to FP4/Int4 degrades output; fee gotchas erode the "no markup" pitch; added latency + second privacy boundary.

Portkey AI Gateway

Mature

Production control plane: sub-ms OSS gateway over 1,600+ models, plus observability, prompt mgmt, 50+ guardrails, governance. Cuts spend three ways: simple + semantic caching, conditional routing to cheapest adequate model with per-team budgets, and granular cost attribution with custom price overrides.

Langfuse

Mature
Why valuable

The cross-cutting gaps — what almost nobody does

Distilled from every tool's individual weaknesses: the things the whole field leaves unmet.

  1. No-regression proof — proving a cost cut didn't degrade output

    Every lever (downgrade, prompt-trim, semantic cache, quantized routing) trades dollars for quality risk, and almost nothing closes the loop. Savers cut blind (OpenRouter quantizes silently; LangCache returns wrong answers at 200 OK). Evaluators (Braintrust, Phoenix, Langfuse) score quality but sit outside the savings path. Nobody ships "route/cache cheaper AND here's the eval proving it still works" as one loop — the single most credible objection to every savings tool, and why teams leave most of the theoretical 30–80% on the table.

  2. Real-time dollars, not tokens, across providers — with alerting

    Dev/observability tools emit accurate tokens and force cost to be derived from a stale, drifting price table. FinOps tools (CloudZero, Finout, Pay-i) speak dollars but run 24–32h behind — useless for catching a runaway-agent spike the day it happens, and their attribution degrades beyond OpenAI/Anthropic. Accurate, real-time, per-call dollars with sub-hour spike alerting is a genuine hole.

  3. A unified "which lever, worth how much on MY traffic" answer

    The market is fragmented by lever — batch wrappers, single caches, manual-config gateways — each optimizing one axis in isolation. None ingest your real usage to output a ranked, quantified menu: "caching saves 18%, 30% of traffic is batch-eligible for +15%, downgrade these 3 calls for 22%, cache break-even is N hits." FinOpsLLM-class consultants charge $1,500–$20k/mo to fill this at the top, leaving the self-serve lane wide open.

  4. Polished self-hosted / air-gapped cost control for regulated buyers

    Every good-UX tool is cloud-only; every self-hostable one carries a tax (Bifrost: no managed option; Langfuse: heavy ops + license traps; Phoenix: scaling cliff + restrictive license). Regulated teams get either good cloud UX they can't use or self-hostable infra with heavy ops burden. Narrower buyer set, but compliance-gated and high willingness-to-pay.

  5. Cost-per-successful-outcome as the optimization target

    The whole stack optimizes cost-per-token. But a cheaper model that fails → triggers a retry, a longer agent loop, or a human escalation makes cost-per-successful-task go UP. Only Pay-i genuinely targets this, and it's enterprise/CFO-only. Retry storms and runaway agent loops — the dominant hidden cost driver in agentic 2026 workloads — are exactly what cost-per-token blinds you to.

The single sharpest opening

Ship a read-only diagnostic that ingests a team's existing LLM usage (billing export or a one-line log drop-in) and returns a ranked, dollar-quantified savings menu on THEIR own traffic — "prompt caching saves 18% / $X · 30% of your traffic is batch-eligible for +15% · these 3 high-volume calls can downgrade for 22% · your cache break-even is N hits" — where each recommendation is backed by a replay-based quality check that proves the cheaper config still passes on a sample of the team's real prompts before they flip it on.

It wins on simplicity: it asks for nothing but logs — no base-URL swap, no SDK rewrite, no sitting in the request path, no infra — so adoption risk is near zero and there's no latency / outage / quantization exposure.

It threads the three biggest gaps at once: the unified "which lever, how much on my data" answer the point tools never give; accurate real-time dollars, not tokens against a stale table; and the no-regression proof loop that makes every savings tool scary. Sell self-serve at the unfilled sub-$20k/mo tier the consultants leave open. Lead with a free one-shot audit (instant, concrete dollar number) as the wedge; only later, once trusted, optionally move into the savings path to auto-apply.

Diagnose first, prove it's safe, then act — trust before traffic.

The honest verdict

The research independently re-derived the opening as a read-only savings diagnostic — i.e. almost exactly the product previously rejected. No dressing that up.

But it found the one ingredient that version never had — gap #1: the no-regression replay proof. The old report said "you're overpaying" (a number — spreadsheet-y, forgettable). The thing nobody in the entire 45-tool field ships is: "turn this lever on, and here's the eval on a sample of your own real prompts proving the cheaper config still passes." That's the difference between a report and a trust instrument that unlocks a scary action.

Don't
Build another gateway / proxy / cache / batch tool. Those five lanes are crowded and incumbents already win on simplicity — native caching is free & automatic; OpenRouter is one URL.
Do
Build the proof layer that sits next to all of them: read-only, ingest logs → replay a sample on the cheaper config → report the quality delta alongside the dollar delta. The missing guardrail that makes everyone else's savings actually get adopted.

Strongest signal in all of this: two independent research passes — one ideation, one live competitor sweep — converged on the same wedge (the replay-proof savings audit) from different directions. That convergence matters more than either pass alone.

The one caveat owed: this is still a diagnostic-first shape, and that's been met with skepticism twice. What makes it different now is the replay proof — but before writing a line of it, the question that actually matters is unchanged: will one real team pay for "prove this cut is safe"? The cheapest way to find out is to run the replay-proof audit by hand on 3–5 teams' logs and see if the output makes them say "take my money."
